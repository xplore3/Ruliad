# Grasp 客户演示脚本

> 面向潜在客户的现场功能演示设计：演示数据、操作步骤、页面跳转、讲解话术、应急预案。
> 全程约 **30–40 分钟**，叙事线与《Grasp-市场推介.pptx》一致：痛点 → 学员练 → 评分复盘 → 管理看板 → ROI 证据 → 资产沉淀 → 行动。

---

## 一、演示前准备

### 环境

```bash
# 仓库根目录
pnpm install && pnpm build
pnpm dev        # 启动 api-gateway(3060) + grasp-web(5173) + admin-web(5174)
```

- **LLM 两种跑法**：
  - 配置了真实 API Key（DeepSeek/Kimi 等）→ 对练回复更生动，**首选**，但依赖网络；
  - 不配 Key → 自动降级为确定性 Mock，全程离线可跑，**作为兜底**。
- **浏览器**：Chrome/Edge。开两个窗口（或一个窗口 + 一个隐身窗口）：左边学员端 `http://localhost:5173`，右边管理端 `http://localhost:5174`。
- **数据重置**：内存模式重启 api-gateway 即恢复种子数据；PostgreSQL 模式执行 `pnpm --filter @grasp-mvp/api-gateway seed`（幂等）。

### 必须改的一处种子数据

种子里的"2026 Q3 L2 认证"考核窗口时间是 **2026-08-01 ~ 08-05**（`packages/infra/src/seed.ts:735`）。
如果演示日期晚于 08-05，考核页会显示窗口已结束。**演示前一天**把 `startsAt`/`endsAt` 改到演示当周，重启服务生效。

## 二、分幕脚本

### 幕 0 · 开场（2 分钟，PPT）

用《Grasp-市场推介.pptx》第 1–2 页开场："销售不是教出来的，是练出来的" → 三个痛点。
话术收尾："接下来 30 分钟，我不讲 PPT 了，直接给你们看正在运行的产品。"

---

### 幕 1 · 学员的一天：3 秒开练（6 分钟）

**目标**：让客户感受"练"的门槛有多低、AI 客户有多像真人。

| 步骤 | 操作 | 讲解话术 |
|---|---|---|
| 1 | 学员端登录 `trainee1 / 123456` → 落到 `/tasks` | "这是销售每天打开的页面：今天练 3 场、约 30 分钟，任务制推着走。" |
| 2 | 指出页面元素：考核倒计时横幅、"继续上次练习"、D7 复训标签、技能地图 | "间隔复习、强制重练都是自动排的，销售不用想今天该练什么。" |
| 3 | 点 **「首访破冰·门诊主任」** 进入 `/session/:scenarioId` | "3 秒进对练。注意看人设卡——陈立国，三甲主任，只有 8 分钟，最反感被推销。" |
| 4 | AI 客户先开口。演示者**正常开场**一轮（自我介绍 + 时间承诺） | "他有脾气：情绪引擎驱动，你说错话他会不耐烦。" |
| 5 | **故意犯错**：输入"我们这款效果特别好，基本上所有患者都能达标，选它稳赚不赔。" | "现在我做一件新人最常犯的错——夸大疗效、违规承诺。看客户的反应。"（注意：红线判定由确定性规则层执行，需命中红线词如"稳赚/保本/保证收益"，这句话已包含） |
| 6 | 客户变脸（皱眉、语气变冷），再聊 1–2 轮后点「结束本次对练 → 进入复盘」 | "练习模式不限次数，说错不用付代价——这就是 AI 陪练的意义。" |

**互动点**（可选，效果好）：把键盘递给客户，"您来扮演销售，跟陈主任聊两句"。客户参与度瞬间拉满。

---

### 幕 2 · 复盘页：每一分都站得住脚（5 分钟）★ 核心幕

**目标**：这是全系统最有说服力的一页，节奏放慢。

| 步骤 | 操作 | 讲解话术 |
|---|---|---|
| 1 | 自动进入 `/session/:id/review`，先看总览卡 | "68 分，较上次 +14；注意红条——刚才那句'所有患者都能达标'触发合规红线，**一票否决，强制重练**。" |
| 2 | 逐项展开评分项 | "每项都有四件套：**判定档位、判定依据、原文定位、更优话术**。不是 AI 拍脑袋打分。" |
| 3 | 点红线条目，展示引用原文 + 更优话术示范 | "它告诉你错在哪一句，还告诉你高手会怎么说——这才叫反馈。" |
| 4 | 指出"判定置信度"说明（双 judge 一致/不一致） | "两位 LLM 裁判独立打分，意见不一致的项目自动标注'参考'，绝不硬判。" |
| 5 | 滑到情绪曲线图 | "客户情绪全程可回溯——你在第几句话说砸了，一目了然。" |
| 6 | 指着「申诉」按钮（先不提交） | "学员不服可以一句话申诉，后面管理端我们会看到这个申诉去了哪。" |

### 幕 3 · 成长与考核（4 分钟）

## 三、避坑清单（演示时不要点 / 怎么答）

| 事项 | 处理方式 |
|---|---|
| 人设页"提交新角色需求"表单 | 不要点提交（功能是占位）。被问到就说"目前由我方顾问配置，工单流程在路线图里" |
| 对练页语音按钮 | 浏览器语音识别可用但依赖 Chrome；**建议全程用文字输入**，避免现场翻车。被问到就说"完整语音链路（ASR/TTS）在 Phase 3 交付" |
| 高管页个别汇总数字 | 部分为演示口径（在册/已认证总数）。不要主动强调具体数字，强调趋势和结构 |
| 练习中途断网 / LLM 超时 | 系统有一次重试 + 兜底话术；若 Mock 模式运行则完全无此问题 |
| 客户问"数据存在哪" | "支持 PostgreSQL 私有化部署；练习/考核数据以会话模式为根隔离，练习明细管理层不可见" |

## 四、应急预案

1. **LLM 调用失败**：拔掉 API Key 重启，切 Mock 模式——回复是确定性的，演示效果依然完整，话术改为"为了演示稳定性，我们跑在离线模式"。
2. **页面状态错乱**：内存模式重启 api-gateway 即恢复种子数据；提前 5 分钟重启一次最稳。
3. **时间不够（只剩 15 分钟版）**：幕 1（压缩到 4 分钟）→ 幕 2 → 幕 6 → 收尾。复盘页和对照组看板是必保的两幕。
4. **客户技术负责人追问架构**：Fastify + 多模型网关（DeepSeek/Kimi/通义/OpenAI/智谱/百川预设）、副裁判强制异模型、React 双前端、PostgreSQL/内存双存储、vitest 测试覆盖评分与情绪引擎。
